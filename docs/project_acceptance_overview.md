# FaceReco 人脸识别监控系统项目说明

## 1. 项目概述

FaceReco 是一个面向多路视频监控场景的人脸识别与考勤管理系统。项目以 Python 为核心后端，结合 OpenCV、YOLO、InsightFace ArcFace、表情识别模型和 Flask Web 前端，实现了从摄像头视频采集、人脸检测、人脸识别、表情分析、人员录入、模型更新到考勤日志管理的一体化流程。

系统既保留了原有桌面端能力，也新增了网页端前端，使用户可以通过浏览器完成监控查看、摄像头配置、人脸录入、模型更新、日志查询和报表导出等操作。网页端重点优化了实时视频流畅度，将画面渲染、人脸检测、人脸跟踪、身份识别和表情识别拆分为相对独立的异步任务，减少深度学习推理对视频刷新造成的阻塞。

## 2. 项目特色

### 2.1 基于深度学习的人脸识别链路

项目的人脸识别主链路采用“人脸检测 + 人脸特征提取 + 向量相似度匹配”的深度学习方案。

系统使用 YOLOv8-face 或 InsightFace 检测模型定位画面中的人脸区域，再使用 InsightFace ArcFace 模型提取人脸 embedding 特征向量。每个已录入用户会在模型更新阶段生成一个稳定的人脸特征中心向量。运行时，系统将当前摄像头画面中检测到的人脸向量与已录入人员的特征向量进行余弦相似度比较，选择相似度最高且超过阈值的人员作为识别结果。

这种方式相比传统 LBPH 等浅层算法具有更强的鲁棒性，能够更好地适应光照变化、姿态变化、摄像头角度变化和不同画面质量。

### 2.2 多路视频监控

系统支持多个监控窗口同时运行，每个窗口可以独立配置：

- 视频源
- 窗口名称
- 显示模式
- 是否进行人脸检测或识别

显示模式包括：

- 人脸识别模式
- 人脸检测模式
- 纯显示模式

用户可以按需启动单个摄像头，也可以一键启动或停止全部监控窗口。

### 2.3 网页端前端

项目新增 Flask Web 入口，用户可以通过浏览器使用系统功能。网页端提供：

- 登录与注册
- 实时监控
- 摄像头配置
- 人脸录入
- 模型更新
- 模型重置
- 用户删除
- 考勤日志查询
- 缺勤统计
- 考勤汇总
- CSV 报表导出

网页端采用 MJPEG 视频流展示实时画面，并在服务端完成检测框、姓名和表情标签绘制，降低浏览器端复杂度。

### 2.4 异步识别与流畅渲染

人脸识别属于计算密集型任务，若将识别推理和视频渲染放在同一同步流程中，会导致画面卡顿。项目在网页端将任务拆分为多个异步流水线：

- 视频读取和画面推送负责持续刷新画面
- 人脸检测和跟踪负责更新当前帧检测框
- 身份识别负责低频更新人员姓名
- 表情识别负责独立更新心情标签
- 日志记录负责节流保存识别事件

这种结构使系统即使在 CPU 推理或 GPU 资源不足时，也能尽量保持监控画面的连续性。

### 2.5 人脸录入与模型更新

系统提供网页端人脸录入功能。用户输入姓名并选择视频源后，系统会调用摄像头采集人脸样本，保存到对应用户目录。采集完成后，用户可以执行模型更新，系统会重新读取全部样本，提取人脸特征，并生成新的识别模型。

如果录入摄像头正在被监控窗口占用，系统会临时释放该监控窗口，完成录入后再自动恢复，保证录入流程和监控流程不会争抢同一摄像头资源。

### 2.6 表情识别与考勤记录

系统在人脸识别成功后，会对对应人脸区域进行表情识别，并将识别到的姓名、地点、时间、表情和考勤类型写入日志数据库。表情模型不可用时，系统会自动降级为默认中性表情，保证主流程不被中断。

考勤日志支持查询、筛选、汇总、缺勤统计和导出，能够满足基础考勤管理与验收演示需求。

### 2.7 GPU 与 CPU 兼容

系统优先使用 GPU 加速深度学习推理。在 CUDA、cuDNN、PyTorch 或 ONNXRuntime GPU 环境不可用时，系统可以自动回退到 CPU 或备用检测器，避免因为单个加速依赖异常导致整个系统无法运行。

系统支持的相关环境变量包括：

- `FACE_RECO_YOLO_DEVICE`
- `FACE_RECO_ORT_PROVIDER`
- `FACE_RECO_WEB_LABEL_MIN_CONF`
- `FACE_RECO_WEB_FAST_TRACK_GAP`
- `FACE_RECO_WEB_RECOG_GAP`
- `FACE_RECO_WEB_RECOG_WIDTH`

通过这些参数可以在准确率、延迟和设备负载之间进行调节。

## 3. 系统主要功能

### 3.1 用户登录与权限隔离

网页端提供登录入口。用户登录后才能使用监控、摄像头配置、人脸录入、模型更新和日志查询等核心功能，避免未授权访问。

### 3.2 实时监控

用户可以在浏览器中查看多路实时视频流。系统在视频画面上叠加人脸检测框、识别姓名、表情标签和运行状态。

### 3.3 摄像头配置

系统支持配置多个监控窗口的视频源、显示模式和窗口名称。配置保存后可以立即应用。

### 3.4 人脸录入

用户输入姓名后，系统从指定视频源采集人脸样本。采集过程中会显示预览画面、采集进度和检测框。

### 3.5 模型训练与更新

系统会根据已录入用户样本重新提取人脸特征，生成用于识别的人脸模型。网页端采用后台训练方式，避免模型更新时页面长时间卡住。

### 3.6 人脸识别

系统在识别模式下自动检测画面中出现的人脸，并将其与已录入人员进行匹配。匹配成功后在画面中显示人员姓名，并记录识别事件。

### 3.7 表情识别

系统对识别成功的人脸进行表情分析，并在画面中显示心情标签。表情结果也会写入考勤日志。

### 3.8 日志与考勤

系统支持：

- 识别日志查询
- 按人员、地点、时间、考勤类型筛选
- 缺勤名单查看
- 考勤汇总
- CSV 报表导出
- 日志清空

## 4. 深度学习人脸识别实现原理

### 4.1 人脸检测

系统首先从摄像头读取视频帧。对于每一帧，检测模块会定位画面中的人脸区域，输出人脸框坐标。项目优先使用 YOLOv8-face 检测器。YOLO 是一种单阶段目标检测模型，可以在一张图像中快速定位多个目标，因此适合实时人脸检测场景。

当 YOLO 模型或 GPU 设备不可用时，系统可以回退到 InsightFace 检测器或 OpenCV Haar 级联检测器，从而提高系统兼容性。

### 4.2 人脸特征提取

检测到人脸后，系统会裁剪人脸区域，并使用 InsightFace ArcFace 模型提取人脸 embedding。embedding 是一个高维向量，它不是直接保存图片，而是保存人脸在深度神经网络特征空间中的表示。

同一个人的不同照片在特征空间中距离较近，不同人的人脸向量距离较远。系统正是利用这个特征完成身份识别。

### 4.3 人脸模型训练

在人脸录入阶段，系统会采集某个用户的多张人脸样本。模型更新时，系统对每张样本提取 embedding，然后按用户 ID 聚合这些向量，计算该用户的特征中心。

最终模型保存的是：

- 用户 ID
- 用户名映射
- 每个用户的人脸特征中心向量

这使识别模型体积较小，更新速度相对较快，也便于后续增删用户。

### 4.4 在线识别

实时识别时，系统对当前帧中的每张人脸提取 embedding，并与模型中保存的所有用户特征中心进行相似度计算。

系统使用余弦相似度衡量两个特征向量的接近程度：

- 相似度越高，表示越可能是同一个人
- 相似度低于阈值时，系统将其视为未知人员
- 相似度最高且超过阈值时，输出对应姓名

为减少陌生人误判，网页端默认提高了标签显示阈值。阈值可以通过 `FACE_RECO_WEB_LABEL_MIN_CONF` 调整。

### 4.5 多人脸识别

检测器会返回一组人脸框，系统对每个人脸分别提取特征并进行匹配。因此在同一画面中出现多个人时，系统可以分别输出多个检测框和对应人员标签。

### 4.6 异步流水线优化

完整人脸识别推理耗时较高，尤其在 CPU 模式下更明显。为了保证画面流畅，网页端将人脸识别拆分为多个异步任务：

1. 当前帧轻量检测用于实时更新检测框位置。
2. 完整识别任务低频运行，用于更新姓名。
3. 表情识别任务独立运行，用于更新心情标签。
4. 渲染线程持续使用最新可用结果合成画面。

因此即使某一次识别推理耗时较长，视频画面也不会等待它完成，而是继续显示当前帧和最近一次稳定识别结果。

## 5. 系统架构

项目主要结构如下：

```text
run_web.py
  网页端启动入口

web_app/
  server.py
    Flask API、登录鉴权、摄像头控制、人脸录入、模型训练、日志接口
  runtime.py
    网页端视频流运行时、异步检测、跟踪、识别、表情和渲染
  static/
    网页端 HTML、CSS、JavaScript

services/
  face_detector.py
    YOLO / InsightFace 人脸检测封装
  face_recognition_service.py
    人脸识别核心服务，负责模型加载、训练、特征提取和匹配
  emotion_service.py
    表情识别服务
  attendance_service.py
    考勤相关逻辑

app/
  services/app_service.py
    业务服务编排
  services/recognition_pipeline.py
    识别流水线与后端选择
  repositories.py
    配置、模型、数据、日志持久化
```

## 6. 验收关注点

验收时建议重点演示以下内容：

1. 网页端登录后进入系统。
2. 配置摄像头并启动实时监控。
3. 切换人脸检测模式，展示检测框。
4. 切换人脸识别模式，展示姓名和表情标签。
5. 录入新人脸样本。
6. 更新模型后重新识别该人员。
7. 查看识别日志和考勤记录。
8. 导出 CSV 报表。
9. 展示多路摄像头同时运行。
10. 展示识别阈值、GPU/CPU 降级和异步渲染优化能力。

## 7. 总结

FaceReco 项目实现了一个完整的人脸识别监控与考勤管理系统。项目的核心价值在于将深度学习人脸检测、ArcFace 人脸特征识别、表情识别、实时视频监控、人员录入和考勤日志管理整合到统一系统中。

系统不仅具备基础功能完整性，也针对实时监控场景进行了工程优化：通过异步流水线、轻量跟踪、识别结果缓存和设备降级机制，在保证识别能力的同时尽量提高视频流畅度和系统稳定性。
